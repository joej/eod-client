# Open questions and oddities

Things we noticed that look odd, are unconfirmed, or may differ between OpenDAoC and the retail
(Mythic / EA / Broadsword) servers. Resolving them adds to what the community knows about the
protocol. Add an entry whenever something surprises us; close it with the evidence that settled it.

**Sources:** `OpenDAoC` = OpenDAoC-Core 2026.09.36 (f0aaa1e) source; `live` = our tests against
that server; `RustDAoC capture` = the recorded 1.127e session in `tests/DaocProtocol.Tests/Fixtures`.

**Ways to resolve:**
- **Retail client capture**: run a real 1.127 client against our OpenDAoC and record it.
  This settles what the *client* sends.
- **Retail server comparison**: compare against the live servers Broadsword still runs. This is
  the only way to settle what a *retail server* replies. It needs their encryption handled and
  a check of their terms of service first, so it's a deliberate decision, not a default step.
- **Historical logs**: PacketLogConverter's decoders and old DaocLogger logs came from retail traffic.
- **Community**: OpenDAoC Discord, DOL forums.

## Retail 1.130 session

One session with the current official client on an official server, recorded on the client
machine with pktmon (2026-10-14, about 70 s: log in, pick a character, walk, quit). The recording
stays private; these are the findings. Times are from the game connection's start.

| # | Oddity | Source | Status / next step |

| R1 | The account login runs first on a separate connection (port 10504; every message is `1b 1b` + u16 BE length + body). Its 13-byte payload reads as a u32 LE length 7, the string `1.130b` + NUL, then u16 `8e 05` (build 1422?). | R6 | **How does the client get the session key?** Neither server sends a key before the client starts encrypting. | E1 | **The 1.130 client crashes on the server's `0xA1` ObjectUpdate (NPC-update) packets — the server sends every client the unchanged 1.68-era format.** 2026-10-22, across 5 in-world sessions. Entry + heartbeat always work; the client renders the static scene (owner saw NPCs "Jula rogue/trader trainer, troll Digby", a center tip dialog), stands still, then crashes ~40–47 s in, self-reporting via a `0x37` crash packet ("Client crash … dll:game_patched.exe clientUptime:47sec").
